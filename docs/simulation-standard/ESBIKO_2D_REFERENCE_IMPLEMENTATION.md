# 2D reference implementation — v1, 2026-10-10

Review URL: https://www.esbiko.com/admin/standards/2d

This is an admin-only SPA page, not a REST API or catalog simulation. Firebase custom claims (`role=admin` or `admin=true`) gate mounting and agent tool registration. Anonymous/non-admin navigation redirects to login. No private server data is exposed. Any future admin API must independently verify the ID token server-side; hiding a route is not API authorization.

## Existing work and design choices

The earlier `SimulationStandardWorkspace`, `SimulationCanvas2DViewport`, `SimulationPanel` and agent/video infrastructure are reused in place. Satellite Tracking contributes camera interaction and the separation of true world coordinates from display scale. The workspace showcase contributes consistent controls and information panels. Existing agent-enabled simulations contribute the shared `useAgentSimulationTools` adapter and `AgentCanvasRecorder`; no second remote protocol or recorder is introduced.

Desktop (MUI lg, 1200px+) has a canvas and 320–380px right rail. Below that breakpoint the canvas precedes playback, controls/camera, measurements/chart, connection and video panels in a vertically scrollable layout. The canvas has a minimum 320px height. Recording-only layouts do not reserve an empty right column. Preserve keyboard sliders, named buttons, status text, touch pointer cancellation and bounded chart memory.

## Source map and development recipe

- `src/components/simulation-ui/Simulation2DReference.jsx`: complete runnable reference adapter and layout composition.
- `standard2dModel.js`: deterministic reference motion, SI unit metadata and parameter ranges. This is a UI demonstration, not a validated domain physics model.
- `SimulationCanvas2DViewport.jsx`: DPR cap, ResizeObserver, bounded frame dt, pointer conversion and cleanup.
- `src/webmcp/useAgentSimulationTools.js`: validated configuration and common state/playback/reset/video tools.
- `src/components/shared/video/AgentCanvasRecorder.jsx`: shared human/agent recorder and actual ready/download state.
- `plop-templates/simulation/Simulation.jsx.hbs`: editable 2D scaffold now uses this composition rather than the older independent shell/loop.

Generate with `npm run gen` (canvas2d), then replace the reference motion import with a local `physics` module and derive the schema, measured quantities and units from the actual science. Customize draw, step, reset and model readback together. Optional legacy helper files generated by Plop remain compatible but are not used by this new main component. The Python scaffolder is a legacy alternative; it has not been migrated and must not be described as producing this standard.

Keep high-frequency scientific state in refs; publish UI/chart snapshots at roughly 10 Hz and retain at most 200 samples. Keep draw callbacks stable where possible. Resize/redraw while paused must not advance physics. A step action advances at most 0.05 simulated seconds before applying the chosen speed. Real numerical adapters must select their own fixed timestep/substeps/error controls; display dt clamping is not a proof of integrator stability.

Camera pan/zoom acts only on the renderer. Dragging and keyboard sliders share the same camera parameters and MCP configure schema. Fit restores the reference camera. The standard currently specifies a virtual scene camera, not webcam capture.

## Agent and video acceptance

The mounted page registers `standard2d_get_state`, `configure`, `set_playback`, `reset`, `start_video`, `video_status`, `stop_video`, `download_video` (each with the `standard2d_` prefix). These call the same setters/refs as the visible controls. If document.modelContext is absent, the connection reads `unsupported`; manual UI still works. This page is intentionally excluded from public MCP server discovery. Future domain simulations must additionally register their manifest and embedded bridge mapping; browser registration alone does not create a remote ChatGPT tool.

Video is browser-side silent WebM, 30 fps, 16:9 or 9:16. Stop finalizes asynchronously; inspect actual ready status before download. Current shared recorder centre-crops to the chosen aspect ratio: frame important objects within that crop. DOM controls/charts are not included. Browser support and host policies apply; no server video job or audio capture is claimed. Navigation cleans up recorder timers/streams without downloading an unfinished file.

Acceptance: build, model/coordinate/parameter tests, Plop template compilation, registry validation and readiness audit; then signed-in admin review at desktop and narrow widths, run/pause/reset/step, keyboard/drag camera, actual browser agent tool mutation/readback, invalid parameter rejection, recording/ready/download and navigate-away cleanup. A build or schema audit is not a substitute for these final browser/media checks.

## Shared science engine — next phase

Do not put orbital, acoustic and optical science into the UI shell. Define an adapter boundary: `initialize(parameters)`, `step(state, dt)`, `measure(state)`, `reset(parameters)`, `serialize(state)`, with explicit units, model version and assumptions. First extract pure vector operations, unit conversions, bounded histories and tested integrators. Pilot the same integrator on two mechanics simulations, compare conservation/error budgets against analytic fixtures, then migrate other domains incrementally. Use model-specific modules where equations differ. Preserve permanent IDs and current browser/server coordinate conventions. This release establishes the reference boundary; it does not claim a unified physics engine has shipped.

## Visual correction — October 10 review

The reference now uses the satellite-style unified dark control rail, flat sections with dividers, quieter grid and compact rectangular buttons. Radius tokens use explicit CSS pixel strings: MUI sx multiplies numeric borderRadius values by theme.shape.borderRadius, which previously produced elliptical/clipped panels. Keep physical design-token lengths explicitly unit-qualified. The generated scaffold also uses absolute shared-component aliases so a new simulation folder resolves its imports correctly.

# Esbiko — Interactive Science and Mathematics Learning Platform

**Esbiko** is a live educational platform for exploring science and mathematics through interactive simulations, visual experiments, classroom workflows, and browser-based scientific media tools.

🌐 **Live platform:** <https://www.esbiko.com>

🧪 **WebMCP Doppler demo:** <https://www.esbiko.com/experiments/physics.acoustics.doppler/run>

## What Esbiko does

Esbiko is designed around learning by experimentation rather than only reading formulas or static diagrams. Depending on the simulation, learners can change parameters, run and pause systems, move scientific objects or observers, inspect calculated measurements, compare scenarios, visualize waves/fields/orbits, and record educational media.

The platform includes and continues to develop experiences across physics, mathematics, astronomy, biology, chemistry, geology, engineering, and interdisciplinary STEM.

### Platform capabilities

- Interactive 2D scientific simulations
- Browser-based 3D simulations and visualizations
- Teacher and student dashboards
- Classroom-oriented workflows
- Scientific challenges and learning activities
- Integrated browser recording tools
- 9:16, 16:9, and square educational media workflows
- Progressive Web App and responsive/mobile foundations
- Firebase-backed authentication, data, storage, hosting, and functions
- Public Platform API foundations
- WebMCP agent-operable science tools

## OpenAI WebMCP Challenge 2026

For the **OpenAI WebMCP Challenge**, Esbiko was extended so an AI agent and a human can operate the **same visible Doppler Effect experiment** together.

This is not DOM-click automation and it is not an embedded chatbot. Esbiko registers semantic website tools through `document.modelContext.registerTool(...)`. Those tools call validated domain adapters and update the same React runtime state used by the visible simulation and human controls.

The result is an agent-operable scientific instrument: an agent can discover the simulation, configure physical parameters, run it, inspect physics-derived measurements, configure a multi-source scene, direct an audible experiment, record a deterministic 9:16 WebM, wait for completion, and download the final file.

### 11 WebMCP tools

**Site tools**

- `list_science_simulations`
- `open_science_simulation`

**Doppler tools**

- `get_doppler_state`
- `configure_doppler`
- `configure_doppler_scene`
- `set_doppler_playback`
- `reset_doppler`
- `create_doppler_video`
- `get_doppler_video_status`
- `stop_doppler_video`
- `download_doppler_video`

The scientific values returned by these tools are calculated from Esbiko's Doppler physics functions rather than generated by an LLM.

## Final default AI Doppler Director

The default `create_doppler_video` experience is a **30-second `two_vehicle` 9:16 WebM story**:

```json
{
  "storyMode": "two_vehicle",
  "durationSeconds": 30,
  "speedMps": 60,
  "emittedFrequencyHz": 440,
  "firstInstrument": "esbiko_voice",
  "secondInstrument": "ambulance_siren"
}
```

The observer is stationary at `500 m`. The timeline is calculated from `distance = speed × time`.

| Time | Source | Motion | Position |
| --- | --- | --- | --- |
| `0–7.5 s` | Esbiko Voice | approaching | `50 → 500 m` |
| `7.5–15 s` | Esbiko Voice | receding | `500 → 950 m` |
| `15–22.5 s` | Ambulance Siren | approaching | `950 → 500 m` |
| `22.5–30 s` | Ambulance Siren | receding | `500 → 50 m` |

At `60 m/s` with speed of sound `343 m/s`, a 440 Hz source is approximately **533.29 Hz while approaching** and **374.49 Hz while receding**.

During an AI-directed recording, the live browser preview and the recorded WebM use the same deterministic director plan, so the user can watch the same movement the agent is capturing.

### Optional 10-second single-pass comparison

For a particularly clear before/after listening test, Esbiko also supports one continuous sound crossing the observer halfway through the recording:

```json
{
  "storyMode": "single_pass",
  "durationSeconds": 10,
  "speedMps": 60,
  "emittedFrequencyHz": 440,
  "firstInstrument": "ambulance_siren"
}
```

This runs the same siren from `200 → 500 → 800 m`, with the observer pass at exactly `5 s`.

## Audio and recording safeguards

The AI Director does not treat the presence of an audio track as proof that the recording is audible.

Before MediaRecorder starts, Esbiko:

1. initializes/unlocks the browser `AudioContext`;
2. preloads the selected recorded instruments;
3. routes the mix through an analyser to both speakers and a `MediaStreamDestination`;
4. runs a short audio preflight;
5. verifies a measurable RMS signal;
6. pauses and restores the scene to exact recording `t=0`;
7. starts the 9:16 recorder and live directed motion together.

If browser autoplay policy blocks audio, the tool returns `AUDIO_ACTIVATION_REQUIRED`. If no real signal reaches the recording bus, it returns `AUDIO_SIGNAL_MISSING` and does not create a silent file.

## Final judge prompt

> Using Esbiko's site tools, create the default 30-second 9:16 two-vehicle Doppler video at 440 Hz and 60 m/s with the observer stationary at 500 m. First show Esbiko Voice crossing left to right, then show an Ambulance Siren crossing right to left. Keep both vehicles visibly moving in the browser and recording, show the higher pitch before each pass and lower pitch after each pass, wait until the recording is ready, then download the WebM video.

## Pre-existing platform vs challenge work

Esbiko is a pre-existing educational platform. Before the challenge it already included the website, simulations, human UI, Doppler scientific model, Firebase deployment, dashboards, platform catalog/API foundations, and media assets.

The WebMCP Challenge work added the agent-facing layer and the end-to-end agent workflow, including:

- WebMCP registration lifecycle and safe feature detection
- 11 semantic website tools
- JSON-safe Doppler adapters and validation
- one/two-source scene configuration
- shared human/agent runtime state
- exact speed×time AI Director timelines
- `two_vehicle` and `single_pass` video modes
- deterministic 1080×1920 WebM recording
- real sample audio preloading and capture
- audio-signal verification and silent-file rejection
- browser autoplay recovery errors
- live browser mirroring of directed recording motion
- structured recording status and download operations
- automated WebMCP contract/physics tests
- hackathon documentation and production evidence

### Scientific layer

Simulations are independent modules that may contain rendering, state, mathematical/physical models, controls, overlays, educational explanations, and recording integration. Technologies across the repository include Canvas, SVG, DOM visualization, Three.js, React Three Fiber, and custom scientific engines.

### Backend and platform layer

Firebase provides hosted infrastructure including Authentication, Firestore, Storage, Hosting, Functions, and security rules. A central catalog/registry provides simulation metadata and public Platform API foundations.

## Local development

Requirements: Node.js and npm.

```bash
git clone https://github.com/amin076/science-web-lab.git
cd science-web-lab
npm install
npm run dev
```

Production checks:

```bash
npm run test:webmcp
npm run test:platform-api
npm run build
```

Do not commit `.env` files, service-account keys, authentication tokens, or production credentials.

## Deployment

Esbiko uses a branch/PR workflow with GitHub Actions and Firebase Hosting. Approved changes are merged to `main`, then the Firebase deployment workflow publishes the production build.

## Accessibility and educational design

Esbiko aims to support responsive layouts, repeatable experiments, clear visual feedback, adjustable parameters, multiple learning formats, and teacher/student workflows. Accessibility and mobile usability remain ongoing development areas.
